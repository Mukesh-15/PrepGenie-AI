# PrepGenie AI — Project Documentation & Interview Guide

> **AI Technical Interview Preparation System**  
> **Tech Stack:** React (Vite) + FastAPI + LangChain + ChromaDB + Ollama (`llama3.1`)

---

## 1. Project Overview

PrepGenie AI is an interview preparation web app that conducts personalized, adaptive technical interviews based on a candidate's uploaded resume PDF.

### How it works at a glance:
1. **Upload Resume:** The candidate uploads their resume PDF.
2. **RAG Ingestion:** Text is extracted, split into chunks, embedded with HuggingFace (`all-MiniLM-L6-v2`), and stored in ChromaDB.
3. **Adaptive Interview:** Questions are generated by an LLM (`llama3.1`) grounded in resume context. If a candidate struggles on a topic, the system automatically asks a simpler follow-up on that topic; if they answer well, it switches to a new topic.
4. **Answer Evaluation:** Every answer is scored on Technical Accuracy, Communication, and Problem Solving (0–10) using a rubric.
5. **Final Performance Report:** At the end, the LLM aggregates all evaluations into a 0–100 score report with strengths, weak areas, and a recommended learning roadmap.

## 3. Project Structure & File Guide

### Frontend (`client/`)
- **`src/App.jsx`**: Main application container managing top-level flow (`upload` → `interview` → `report`).
- **`src/index.css`**: Design system tokens (colors, buttons, badges, typography) for the clean white theme.
- **`src/components/Navbar.jsx`**: Clean header showing app title and reset button.
- **`src/components/UploadResume.jsx`**: Minimal PDF drag-and-drop upload screen.
- **`src/components/InterviewSession.jsx`**: Question card, retrieved resume context accordion, answer textarea, and submit button.
- **`src/components/EvaluationCard.jsx`**: Displays per-question feedback, scores (Technical, Communication, Problem Solving), strengths, and weaknesses.
- **`src/components/ScoreGauge.jsx`**: Compact, clean score bar component.
- **`src/components/FinalReport.jsx`**: End-of-interview summary showing overall score (0–100), detailed feedback, competencies, and study roadmap.
- **`vite.config.js`**: Configures Vite dev server to proxy `/api` requests directly to FastAPI at `http://localhost:8000`.

### Backend (`ai-service/`)
- **`app/main.py`**: FastAPI entry point, enables CORS, mounts interview router, and provides `/health`.
- **`app/config.py`**: Loads environment variables (Ollama URL, model name, ChromaDB path, port).
- **`app/schemas.py`**: Pydantic models for structured LLM inputs/outputs (`InterviewQuestion`, `AnswerEvaluation`, `FinalReport`, `SubmitAnswerRequest`).
- **`app/store.py`**: Thread-safe in-memory session store tracking active interviews, questions, answers, and evaluations.
- **`app/routers/interviews.py`**: REST API endpoints for upload, fetching questions, submitting answers, and generating reports.
- **`app/services/resume_processor.py`**: Extracts text from PDF via `PyPDFLoader`, splits into chunks using `RecursiveCharacterTextSplitter`, creates embeddings, and saves into ChromaDB.
- **`app/services/question_generator.py`**: Retrieves relevant resume context from ChromaDB and prompts Ollama to generate grounded, adaptive interview questions.
- **`app/services/answer_evaluator.py`**: Evaluates candidate answers using a 3-part rubric (Technical, Communication, Problem Solving) with Ollama.
- **`app/services/report_generator.py`**: Aggregates all per-question evaluations into a final comprehensive performance report.

## 4. End-to-End Data Flow

1. **Upload Resume**:
   - User drops a PDF in the React UI.
   - `POST /api/interviews/upload` sends the file to FastAPI.
   - `resume_processor.py` extracts text, splits it into 1000-character chunks with 200-character overlap, generates embeddings, and saves them in ChromaDB under a unique `session_id`.
   - `store.py` creates an interview record and returns `interviewId` to the frontend.

2. **Generate Next Question**:
   - `POST /api/interviews/{interviewId}/question` is called.
   - `question_generator.py` checks interview history:
     - If the previous answer scored $\le 5$, it triggers a follow-up on the same topic.
     - If the previous answer scored $> 5$, it searches ChromaDB for a new topic from the resume.
   - Ollama generates an `InterviewQuestion` JSON object matching the Pydantic schema.
   - Question is saved in `store.py` and returned to the UI.

3. **Submit & Evaluate Answer**:
   - User types an answer and submits.
   - `POST /api/interviews/{interviewId}/answer` sends `{ questionId, answer }`.
   - `answer_evaluator.py` retrieves resume context for fact-checking and prompts Ollama with a strict scoring rubric.
   - Ollama returns `AnswerEvaluation` with scores (0–10), strengths, weaknesses, and constructive feedback.
   - Saved in `store.py` and displayed on the UI.

4. **Generate Final Report**:
   - User clicks "End Interview & Generate Report".
   - `POST /api/interviews/{interviewId}/report` collects all completed evaluations.
   - `report_generator.py` prompts Ollama to aggregate all results into a 0–100 scale report with overall feedback, strong areas, weak areas, and learning suggestions.
   - Saved in `store.py` and displayed in `FinalReport.jsx`.

## 5. Key Technical Concepts & Design Decisions

- **RAG (Retrieval-Augmented Generation)**: Grounding LLM prompts in resume chunks prevents hallucinations and ensures questions are directly relevant to the candidate's actual background.
- **Structured Outputs (`with_structured_output`)**: LangChain forces the LLM to strictly return valid JSON that validates against Pydantic models. No fragile regex or manual text parsing needed.
- **Adaptive Difficulty**: Dynamically adapts interview flow based on previous question performance rather than following a static script.
- **Temperature Tuning**:
  - `0.7` for Question Generation (creative, varied questions).
  - `0.3` for Answer Evaluation (consistent, reproducible scoring).
  - `0.4` for Final Report (balanced analytical summary).
- **Consolidated 2-Tier Architecture**: Removed unnecessary Express middleman, allowing FastAPI to handle both API state and AI workloads directly.

## 6. Top Interview Questions & Answers from this Project

### Q1. Can you explain the high-level architecture of this project?
> "The project is a 2-tier full-stack application. The frontend is built with React and Vite, styled with Tailwind in a clean, minimal design. The backend is a FastAPI Python service that uses LangChain to connect ChromaDB for vector retrieval and local Ollama (`llama3.1`) for LLM inference. When a candidate uploads their resume, we chunk and embed the PDF text into ChromaDB. During the interview, questions are generated using RAG based on the candidate's resume, answers are evaluated against a rubric, and a final aggregated performance report is generated."

---

### Q2. What is RAG and why did you use it here?
> "RAG stands for Retrieval-Augmented Generation. Instead of asking the LLM to generate generic questions from its training weights, we search the candidate's embedded resume in ChromaDB for relevant sections (like projects, skills, or experience) and insert those chunks directly into the prompt. This grounds the LLM in real context, avoids hallucination, and makes every question specifically tailored to what the candidate has done."

---

### Q3. Why did you choose ChromaDB and local Ollama?
> "ChromaDB is a lightweight, embedded vector database that runs locally in-process and persists data to disk without needing complex external infrastructure. Ollama lets us run open-source models like `llama3.1` locally, meaning zero API cost and full data privacy since resumes never leave the local environment."

---

### Q4. How does structured output work with LangChain and Pydantic?
> "We define Pydantic models (like `InterviewQuestion` and `AnswerEvaluation`) with typed fields and descriptions. Using `llm.with_structured_output(Schema)`, LangChain binds the schema to the LLM via tool-calling or JSON mode. The LLM is forced to return structured JSON that Pydantic validates automatically, ensuring type safety and preventing parsing crashes."

---

### Q5. How does the adaptive interview logic work?
> "In `question_generator.py`, we inspect the score of the previous answer from the session history. If the candidate scored 5 or below, the prompt instructs the LLM to ask a follow-up on the same topic from a simpler angle to probe deeper. If they scored above 5, it searches ChromaDB for an uncovered topic from their resume. This mimics the behavior of an experienced human interviewer."

---

### Q6. How do you handle session state without a database like MongoDB?
> "We implemented a thread-safe in-memory store in `store.py` using Python's `threading.Lock()`. It maintains a dictionary of active interview sessions, questions, evaluations, and reports keyed by a UUID `interviewId`. This keeps the application fast, lightweight, and self-contained without requiring an external database instance."

---

### Q7. How do the frontend and backend communicate?
> "The frontend uses `axios` to make standard REST requests to `/api/interviews/...`. In development, Vite's dev server proxies any request starting with `/api` to `http://localhost:8000`. This avoids CORS issues and keeps API paths clean and relative."

---

### Q8. What would you improve to make this production-ready?
> "1. Replace the in-memory store with PostgreSQL or Redis for persistent, multi-instance storage.  
> 2. Add user authentication (JWT) so users can save and revisit past interview reports.  
> 3. Add audio support with Web Speech API or Whisper for voice-based mock interviews.  
> 4. Support cloud LLMs (like OpenAI or Gemini) alongside Ollama with a toggle in `.env`."
